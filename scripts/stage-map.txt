# Which harness stages a changed path can affect, read by scripts/stages-for.py (`just stages-for <base> <head>`).
#
# Each rule is `<path pattern> <selection>...`; the first rule whose pattern matches a changed path decides it, and a
# path no rule matches selects the full default suite. Patterns are repository paths: `*` and `?` stay inside one
# directory, `**` spans any number of them (`a/**/b` includes `a/b`).
# Selections:
#   <stage> or <stage glob>  that stage, or the default stages the glob names (`client-*`)
#   @full                    the whole default suite
#   @none                    no stage (docs, tooling, unit and integration tests that cargo test runs)
#   @module                  the stages whose code includes this file: a stage's module in crates/harness/src/stages,
#                            the modules it names (`super::m`, `crate::stages::m`) and their own, its scenario
#                            (crates/harness/scenarios/*.cfg); a server scenario stage includes stages/server.rs
#   @client                  every default stage except those on the `no-client:` line, so a new stage is in it
#   @web                     the stages whose code starts the browser client (`browser_cdp`, `COD4E_WEB_DIR`)
#   @uses:<crate>            the stages whose code calls <crate>:: in the harness process
#   +timing                  also the timing set below (every engine change: the crates the binaries build from)
# Stage facts are read from the head ref (crates/harness/src/stage.rs and stages/*.rs), so new stages and helper
# modules are picked up without editing this file.
